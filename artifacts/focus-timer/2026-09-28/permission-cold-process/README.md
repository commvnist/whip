## Limits and diagnostics

- Android retains the earlier native record on runtime revocation here. Permission=false is verified, but revocation alone is not absence-of-notification evidence. The fresh denied session separately proves that no running notification is published under denial.
- The initial drawer PNG catches animation and native hierarchy dumping reports no idle state. It is diagnostic; only the settled screenshot drives the cold Stop tap. The driver now removes any previous dump and rejects unsuccessful fresh dumping, so stale hierarchy output cannot drive accepted interactions. In-process native campaigns retain paired drawer originals through their independent capture path.
- The first cold-Open capture sees the normal launch splash and native dumping returns a null root; it is diagnostic. The later settled inspector/native hierarchy and new-PID/current-pair facts establish the successful route. No launch-latency claim is inferred from the time between manual observations.
- Early driver setup incorrectly used the release package or absent editor/Home selectors; these attempts did not create a timer or contribute acceptance. The successful protocol targets the .debug package and native visible names.
- Pair/deadline stability is asserted for permission return. This cold-start journey does not assert WorkManager UUID stability; the in-process presentation-only refresh tests cover that separately.
- No owner phone, private records, physical-device reset/instrumentation, force-stop guarantee or Play release is involved. The script is deliberately fixed to the disposable emulator.
