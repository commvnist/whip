## Finding and decision

The editor offered Date Field `is between`, but `TrackAnalytics.matches` routed `Between` only through `numericValue`; valid Date Field ranges therefore produced no Entries. The new typed-operator test initially failed at the exact Date-range assertion, then passed after dispatching by Field type. The final native journey creates an authored `Observed` Date Field and five Entries whose Entry Dates are all Sep 5 but whose `Observed` values run Sep 1–5. It applies an `Observed` Sep 2–4 range in history and Insights, proves exactly three matching rows and Total 3, recreates the Activity on both screens and verifies unchanged saved projections. The initial native fixture used the special Entry Date (which already worked); its capture is superseded by this corrected journey.

The repository also made one suspending DAO call per imported value and assembled the complete invalidated graph on the collector's dispatcher. Existing UI consumers observe from the main dispatcher. The final implementation keeps the existing one-transaction import, stable identities, FTS, checkpoints, receipt idempotency and full read model, but writes bounded 100-row list batches and shifts projection mapping to `Dispatchers.Default`. A larger summary/partial-projection redesign is deferred because the measured supported maximum is usable and that redesign would change search, insights, exports and Home contracts together.
