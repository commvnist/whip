# Pinned Habit Tracking widget through a managed process kill

This is an actual Pixel Launcher-hosted Habit Tracking widget on a disposable API 34 emulator with current debug Whip and completed Setup. The widget was pinned from the Whip Dev launcher picker. `replay.py` requires that precondition, refuses non-emulators/other APIs, adds one uniquely named synthetic Habit through the widget's Add action, and does not clear other data. It confirms the default `Daily|CheckOff` record and zero logs, renders the exact row, kills Whip through Android's cached-process manager while Settings is foreground, returns Home, checks off the row, then reverses that action from the widget. Exact Room facts and a new PID are required at each boundary.

The accepted `run-api34/proof.json` records Habit 3 and PID 6051 to 6573. The row remains visible across the kill. Check-off produces one `Success|1.0` log and changes the widget action to “Mark incomplete”; the reverse control removes that log and restores “Mark complete.” The app-level Habit created during manual exploration remains on this disposable emulator, so the replay asserts by its unique Habit ID rather than requiring an otherwise empty widget.

Five original 1080×2400 PNG/XML pairs were individually inspected: pinned widget before Add, due row, recovered due row, completed row, and reversed due row. The two-line synthetic title remains readable, the state/control reflect the Room transition, and all five XMLs have zero `NAF=true` nodes. The replay enforces that absence for Whip-owned nodes. Supplemental launcher-host states `platform.widget.habit-tracking.before`, `.due`, `.after-process-death`, `.completed`, and `.reversed` map respectively to `pinned-habit-before`, `pinned-habit-row`, `pinned-habit-after-kill`, `pinned-habit-completed`, and `pinned-habit-reversed` in `run-api34/`. These five states sit beside the 528-state in-app capture catalog; they are not silently counted as completed catalog capture.

This covers the check-off Add/complete/undo path on this launcher/API. Checklist, count, measurement and timer actions, widget configuration/resize on diverse launchers, cross-day behavior, TalkBack speech and whole-product acceptance remain open. No production source, schema, backup format, data epoch, version, owner-phone install or release changed in this checkpoint.
