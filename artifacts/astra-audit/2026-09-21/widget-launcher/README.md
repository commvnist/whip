# Pinned Task Agenda widget through a managed process kill

Scope: a disposable API 34 Pixel Launcher with one real Task Agenda widget pinned from the launcher picker, current debug Whip, and completed Setup. The widget was dragged from the Whip Dev picker onto an otherwise empty Home page; Android assigned widget ID 3 to the launcher host. `replay.py` requires that precondition and refuses a physical device or other API. It does not clear other synthetic data. A fresh unique scheduled Task is created through the widget's Add control and production Task editor, rendered in the launcher's RemoteViews collection, retained across Android's cached-process kill, then completed by the widget row control. Room must report a non-null completion timestamp, the row must disappear, and a new Whip PID must replace the old one.

## Baseline and correction

The pre-fix `run-api34/` replay succeeds functionally: Task 3 is created and completed, and Whip moves from PID 2097 to 3568. However, each of its four original launcher XML captures contains `NAF="true"` on `widget_brand`: a separate 32dp clickable ImageView with no label, duplicating the adjacent labeled header. The PNGs show that the widget and Task are otherwise readable. This is the exact FND-20260921-007 baseline, not an assertion that TalkBack speech was exercised.

The final `final-api34/` replay runs after removing PendingIntents from the decorative brand mark in Task, Habit and update-required widgets. The labeled, full-height header still owns navigation; the Add and row actions are unchanged. Task 4 is scheduled, visible before and after managed process death (PID 3668 to 4149), completed through the pinned widget, and removed from the launcher list. Its `completedAtMillis` is in `proof.json`. All four final original 1080×2400 PNG/XML pairs were individually inspected: empty, actionable row, post-kill row and completed empty; no clipping or unlabeled Whip node. Final XML has zero `NAF=true` nodes across all four captures. The replay itself asserts that every Whip-owned visible node is labeled when actionable.

Supplemental launcher-state inventory: `platform.widget.task-agenda.empty` is `pinned-widget-before`, `platform.widget.task-agenda.scheduled` is `pinned-widget-row`, `platform.widget.task-agenda.after-process-death` is `pinned-widget-after-kill`, and `platform.widget.task-agenda.completed` is `pinned-widget-completed`; each has a final PNG/XML pair. These launcher-host states are tracked alongside, not silently counted inside, the current 528-state in-app capture catalog. Their final cross-host disposition remains part of the whole-product audit.
