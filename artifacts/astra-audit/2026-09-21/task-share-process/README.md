# External Task share after Android process death

This is a disposable API 34 emulator journey for the current debug APK, not an owner-phone release. `replay.py` refuses a non-emulator or different API and requires completed Setup. It sends a cold `ACTION_SEND` text share into the production `MainActivity`, edits the unsaved Task title, confirms neither title exists in Room, then backgrounds the Activity, foregrounds Android Settings and asks ActivityManager to kill Whip's cached process. It refocuses the retained task, checks a different PID, verifies the edited unsaved draft and absence of a duplicate share-request prompt, saves once, and checks exactly one edited Task and no original-title Task in Room. It then opens Inbox and requires the saved Task to be visible. The script adds one uniquely named synthetic Task without clearing other emulator data.

Run on a prepared disposable emulator: `python3 artifacts/astra-audit/2026-09-21/task-share-process/replay.py emulator-5556 artifacts/astra-audit/2026-09-21/task-share-process/run-api34`.

`run-api34/proof.json` preserves task/PID and exact database counts. The three original 1080×2400 PNG/XML pairs show the edited draft before death, its restored unsaved form in the new process, and the saved Task in Inbox. The originals were individually inspected for legibility and clipping; XML has no `NAF=true` nodes. This complements, but does not replace, the native `PlatformEntrySurfaceE2ETest` sharing/queue/widget-action cases. It covers a cold, single text share and OS process death, not a pinned RemoteViews widget, simultaneous shares during process death, other MIME types, a physical phone, or whole-product acceptance.
